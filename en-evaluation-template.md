# Evaluation Checklist for the Integration Project

> Evaluation is based on the submitted report and software; there is no presentation component.

## Correctness and Level of Software Completion -- 40\%

### Mandatory Functionality

- [ ] All mandatory functionalities are fully implemented
- [ ] The software runs correctly, with no errors in basic operations
- [ ] Execution instructions are provided (README or description in the report)
- [ ] Input and output are consistent with the specified requirements

### Correctness of Algorithms/Results

- [ ] Results are consistent with the underlying theory
- [ ] Illustrative test examples are provided
- [ ] For analysis-oriented projects (Boolean networks, Petri nets, abstract argumentation frameworks, etc.): results are validated against benchmarks or standard tools (if available)

### Quality of Software Implementation

- [ ] Code is clear and well-structured
- [ ] Comments are sufficient and appropriate
- [ ] File organization is clear and reproducible
- [ ] Installation and setup instructions are detailed and clear

## Quality of the Technical Report -- 40\%

### Structure and Presentation

- [ ] Logical structure: Introduction -- Theory -- Methodology -- Results -- Conclusion
- [ ] Clear writing style, free of spelling and grammatical errors
- [ ] Figures and tables are well-designed and properly captioned
- [ ] References are cited in a proper and consistent format

### Theoretical Understanding

- [ ] Relevant theoretical background is presented correctly and sufficiently
- [ ] Core concepts are clearly explained
- [ ] Content is not copied mechanically without understanding

### Algorithm Description \& System Design

- [ ] Applied algorithms are described in sufficient detail
- [ ] System architecture is clearly illustrated
- [ ] Input/output of each module is clearly described

### Experimental Results \& Evaluation

- [ ] Illustrative experiments are conducted
- [ ] Results are analyzed (not only illustrated with figures)
- [ ] Limitations and potential future directions are discussed

## Creativity \& Added Value -- 10\%

- [ ] Advanced features beyond the basic requirements are implemented
- [ ] User interface is intuitive and easy to use
- [ ] Original analysis or optimization is provided
- [ ] The tool has practical value beyond a basic programming assignment

## Professionalism in Submission -- 10\%

- [ ] Submission is organized as a clearly structured folder or repository
- [ ] A README file is provided with instructions to run the software
- [ ] Environment and dependency installation instructions are included
- [ ] The report is submitted as a cleanly formatted PDF without layout issues

|---------|--------|-------|

| Technical report | **40%** |
